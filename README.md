# mosaico-deck

**桌面上的 agent 状态/交互终端。** ESP-Mosaico (ESP32-S31) + 480×480 AMOLED + 触摸 + USB。

## 它是什么

一块一直亮在桌上、专门服务 coding agent 的小设备：

- **状态常显** —— agent 在改哪个文件、测试过没过、还要多久，一眼看到，不用 Alt-Tab
- **物理批准** —— 按实体键批准/拒绝，比在终端里敲 `y` 更慎重
- **`ask_user`** —— agent 需要澄清时，**在设备上问人**，人按一下，agent 拿到结构化答案
- （规划中）**语音下达** —— 按住说话，不打断手指在键盘上的位置

对外以 **MCP server** 的形式提供能力，所以任何支持 MCP 的 agent 都能用，不需要为
某个 agent 单独适配。

## 架构：为什么界面不在这块板子上渲染

```
┌─ PC 侧（mcp_bridge）──────────────────────────┐
│ agent 调 MCP 工具 → 用它自己的字体渲染 480×480  │
│                    → 编码 → 通过 USB CDC 发下来  │
└───────────────────────────────┬───────────────┘
                                │ USB CDC（一行一条 JSON）
┌─ 板子侧 ───────────────────────▼───────────────┐
│ 显存只有 band 双缓冲 → 收帧 → 显示               │
│ 触摸/按键 → 一行 JSON 回传                       │
└───────────────────────────────────────────────┘
```

**理由不是"板子性能不够"，是开发效率：**

| | 板子渲染 | **PC 渲染** |
|---|---|---|
| 中文字库 | 自己做点阵（1~2MB，难看） | 系统字体，完美且免费 |
| 抗锯齿 / 图标 / emoji | 几乎没有 | 免费 |
| 改一次界面 | **重新烧录** | **存盘即生效** |

最后一行是数量级的差别。板子侧代码越少，"调界面"越快。

而且板子是通过 USB 连在电脑上的 —— 带宽和供电都不是问题。整屏 450KB 传一次约
0.5 秒；**只传变化的那几条 band 的话是几 KB、几十毫秒**（这才是有意义的模式）。

## 现在能用了

**做成 DeepSeek Harness 原生插件**（不是 MCP）。

```bash
# 1. 烧固件（免按键烧录，可反复烧）
./flash.sh

# 2. 装插件（装完自动跑加载自检）
./install-plugin.sh desktop

# 3. 重启 DeepSeek Harness
```

重启后设备上的状态**自动跟着 agent 走** —— 模型一个字都不用说。见
[plugin/](plugin/)。

### 为什么是原生插件而不是 MCP

插件直接挂 DSH 自己的生命周期：

```
agent/status  tools/pre-execute  tools/post-execute
assistant/message  agent/error
```

好处有两条，**MCP 都做不到**：

1. **界面自动跟着走。** MCP 工具得模型主动想起来调，而它经常想不起来。
2. **显示的是事实，不是模型的自我报告。** 状态来自宿主事件里真实的工具名和
   参数，而不是模型说"我在跑测试" —— 那句话可能是编的。

三个工具（`deck_speak` / `deck_ask` / `deck_show`）是补充，不是主力。

### 实测（band 差分）

| 场景 | 发出 | 
|---|---|
| 首次整屏 | 16 条 band / 450 KB |
| 内容完全没变 | **0 条 band** |
| 改一行字 | 2 条 band |

只发改动的 band，所以更新稳稳落在一次面板刷新（17ms）之内，**不会撕裂**；
而整屏 450KB 在 60MHz QSPI 上要 15.4ms，几乎等于刷新周期，稍微一抖就撕裂。

## 复用了什么

显示、触摸、板级识别这三块从 [mosaico-fluidbox](../mosaico-fluidbox) **逐字节原样移植**
（已核对），它们都已在真机上验证过：

| 组件 | 内容 |
|---|---|
| `display/` | CO5300 QSPI AMOLED，**band 双缓冲 + 异步 DMA + TE 同步** |
| `touch/` | CST9220，含"**读失败 ≠ 松手**"那个 100ms 时间去抖 |
| `usb_console/` | TinyUSB CDC + **免按键烧录用完整两步 DTR/RTS 签名** |
| `input/` | AI 按键（短按/长按，**单次 Poll 不共用去抖状态**） |
| `osal/` `config/` | 任务/信号量封装、板级版本 eFuse 识别 |

⚠️ **免按键烧录那条链路是照原样搬过来的，不要改动** —— 详见下面的坑。

## 已经踩过的坑（都写进代码注释了）

1. **板子版本必须读 eFuse**，不能靠 menuconfig 猜。V1.0 和 V1.2 的 `LCD_RST`/`LCD_SCL`
   是**互换**的，选错的症状是"初始化一路 OK 但全程黑屏"（QSPI 只写，主机不知情）。
2. **免按键烧录必须认 esptool 的完整两步签名**（`DTR=0,RTS=1` → `DTR=1,RTS=0`）。
   只认"RTS 下降沿"的话，任何一次串口打开/关闭都会被误判成下载请求 —— 而 S31 rev0
   的 ROM 没有 USB 持久化，端口就永久掉线。**表现是"每次烧完读一次日志设备就没了"。**
3. **QSPI 别超 60MHz**。面板 TE 实测 58.5Hz 才是真实上限，80MHz 只会引入位错误
   （表现是"某条 band 闪一下别的颜色"）。
4. **触摸的"读不出点"不等于"松手"**。I2C 报告会间歇性损坏（日志里能看到
   `Malformed report header`），当成松手会让受力每几毫秒通断一次。
5. **按键的长按/短按必须一次 Poll 出结果**。拆成两个函数会让它们共用同一份去抖
   状态互相踩，双双失灵。

## PC 端依赖

**这块板子本身不需要 PC 就能显示**（烧好固件就亮）。但插件是在 PC 上渲染和发声的，
所以运行插件需要下面这些。缺了不会崩，而是"面板空白""喇叭不响"这类难查的症状 ——
所以先跑一次自检，它会直接告诉你缺什么：

```bash
./check-deps.sh      # 检查
./install-deps.sh    # 安装（macOS 用 brew/pip；其他平台会打印该装什么）
```

| 依赖 | 用途 | 必需 | 平台 |
|---|---|---|---|
| Python 3 + Pillow | 渲染界面（`plugin/render.py`） | **是** | 跨平台 |
| ffmpeg | 语音编解码（朗读与语音输入都要） | 否 | 跨平台 |
| `say` | 语音合成 | 否 | **仅 macOS** |
| whisper.cpp（`whisper-cli`）+ 模型 | 语音转文字（按键说话） | 否 | 跨平台 |

没有可选依赖时会优雅降级，并且**在启动日志和 `deck_connect` 的返回里说明缺了什么**，
不会静默失效：

- 缺 ffmpeg / `say` → 不朗读，日志里说明一次
- 缺 whisper / 模型 → 按住说话时面板显示"需要 whisper"，不做无用的识别

模型放 `~/.cache/whisper/ggml-small.bin`（约 465MB），可用 `DECK_WHISPER_MODEL`
指定别处；`DECK_WHISPER` 可以换用别的 whisper.cpp 可执行文件。

### 平台支持

| | 显示 | 语音播报 | 按键说话 |
|---|---|---|---|
| macOS | ✓ | ✓（`say`） | ✓ |
| Linux | ✓ | ✗ 需自己接一个 TTS（如 espeak-ng） | ✓ |
| Windows | 未验证 | 未验证 | 未验证 |

**目前只在 macOS 上开发和实测过。** 代码里平台相关的部分集中在两处：`plugin/lib/tts.js`
里的 `say`，以及 `plugin/lib/device.js` 里的串口节点匹配（`/dev/cu.usbmodem*`）。
移植的难点主要在后者——不同系统的串口命名与"控制口 vs 数据口"的配对方式不一样。

## 烧录

```bash
./flash.sh          # 应用在跑时用：自动探测端口 → knock → 烧录
./flash-rom.sh      # 已经在下载模式时用：不 knock，直接烧
./check-board.sh    # 只诊断，不碰端口
```

**分工必须干净** —— "自动判断该用哪个"的代价很大，因为判断本身就要打开端口，
而**打开端口这个动作本身就是复位信号**。
